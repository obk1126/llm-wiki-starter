# Verification Panel — 산출물 페르소나 검증단

산출물을 만든 눈으로는 산출물의 구멍이 안 보인다. 서로 다른 렌즈의 페르소나 에이전트를 **병렬로** 돌려 발표 전에 구멍을 찾는다.

## 검증단 기본 구성 (5석 — 렌즈 분리가 핵심)

| 자리 | 페르소나 | 렌즈 |
|---|---|---|
| 구매자 | 이 산출물로 설득해야 할 의사결정자 | 설득 논리·결정 가능성·비용 질문 |
| 리스크 보유자 | 가장 보수적인 이해관계자 (법무·보안·재무 성향) | 민감정보·과장 탐지·공격 질문 시나리오 |
| 실사용자 | 산출물이 말하는 것을 실제로 쓸 사람 | "내 일의 어떤 순간인가"·용어·분량·수용성 |
| 양식 감사관 | 자기 조직의 문서·발표 규약 담당 | 규약 준수·톤·단정어 적발 |
| 사실검증관 | 기술 감사 | 모든 수치·주장을 **원천(저장소·데이터) 직접 조회로 대조** |

- 볼트에 검증 방법론 노트가 있으면 **그 노트를 먼저 Read**하고 구성·규칙은 노트를 따른다 (노트가 정본).
- 필요 시 옵션석 추가(디자인 감사·접근성 등). 렌즈가 겹치면 둘 다 얕아진다 — 겹침 금지.

## 절차

1. **대상 파악** — 산출물 파일 경로, 청중, 발표 맥락, 민감 요소(실명·실데이터·계약 조항).
2. **병렬 실행** — Agent 툴로 전 좌석을 한 메시지에서 동시에 띄운다. 좌석별 프롬프트에 반드시:
   - 페르소나 정체성(역할·성향·두려움)과 렌즈 1개
   - 산출물 파일 경로 (이미지·캡처가 있으면 직접 열어보라는 지시)
   - **사실검증관에게는 원천 접근 권한**(레포 경로·데이터 조회 지시) — 문서만 보면 그럴듯한 오류를 못 잡는다
   - 출력 형식 강제: `[치명]/[중요]/[제안]` + 위치 + 해당 문구 + 수정 제안, 등급순
3. **종합·반영** — 치명은 전건 반영, 중요는 사용자 판단이 필요한 것만 질문으로 올림. 검증단의 답이 곧 정답이 아니다 — 상충하는 지적의 수위 결정은 사용자에게 넘긴다.
4. **역기입** — 새로 발견된 실패 패턴은 볼트의 검증 방법론 노트에 추가한다 (실행 → 위키 역수입 루프).

## 종결 판정
라운드 반복 시 "지적 0건"이 아니라 **층위 하강**(사실 오류 → 통합 정합성)이 수렴 신호다.
